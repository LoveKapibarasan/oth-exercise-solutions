Exercise 5.3 [Cardinalities, Keys, Foreign Keys, Totality]

a)

  • To ensure a one-to-one relationship between students and advisors, I need to add a UNIQUE constraint on i_id.
  • The existing primary key on s_id already ensures each student can have at most one advisor, but without the UNIQUE constraint on i_id, multiple students could be assigned to the same instructor.
  • Adding UNIQUE on i_id ensures each instructor can advise at most one student, completing the one-to-one relationship.

b)

  • A superkey is any set of attributes that can uniquely identify a tuple in a relation, though it may contain redundant attributes.
  • A candidate key is a minimal superkey—it uniquely identifies tuples but contains no unnecessary attributes that could be removed while still maintaining uniqueness.
  • A primary key is the candidate key chosen by the database designer to be the main identifier for the relation, and it cannot contain null values.

c)

  • In SQL, we cannot express that the A-side is total because key and foreign key constraints only enforce referential integrity in one direction—from the referencing table to the referenced table.
  • The foreign key in the A_B relationship table references A, but there is no mechanism in standard SQL key/foreign key constraints to enforce that every tuple in A must have a corresponding tuple in A_B.
