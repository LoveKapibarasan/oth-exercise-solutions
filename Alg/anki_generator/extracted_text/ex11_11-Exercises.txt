11.1Transposition Tables
In this exercise, you will enhance your Alpha-Beta Pruning implementation with a Transposition Table
(TT) using Zobrist Hashing to avoid evaluating the same board positions “too often”.
a)Zobrist Hashing and SeedingImplement Zobrist Hashing. You will need to generate a table of
random 64-bit integers for each possible piece placement. Use the following provided function
init zobrist()to seed your random number generator and fill this table.
staticuint64_t zobrist_table[2][NUM_COLS][NUM_ROWS];
voidinit_zobrist(void)
{
// xorshift * pseudo random number generator
uint64_t seed = 0x123456789ABCDEFULL;
for(intp = 0; p < 2; p++) {
for(intc = 0; c < NUM_COLS; c++) {
for(intr = 0; r < NUM_ROWS; r++) {
seed ˆ= seed >> 12;
seed ˆ= seed << 25;
seed ˆ= seed >> 27;
zobrist_table[p][c][r] = seed * 0x2545F4914F6CDD1DULL;
}
}
}
}
Note that because index collisions are resolved by verifying the complete board position, your
algorithm will never yield incorrect results regardless of the exact seeding function used. You
are free to implement your own seeding function instead of the one provided above.
Modify yourmake moveandundo movefunctions to incrementally update the Zobrist hash of
the current board and the Zobrist hash of the mirrored board position using XOR operations.

d)AnalysisCompare the execution times. You will likely observe that increasing the TT size im-
proves performance up to a certain point (e.g., 1 GB), but making it very large (e.g., 16 GB) causes
the execution time to increase again, even if the table completely fits into your physical RAM and
no swapping occurs. Get informed about hardware architectural reasons for this phenomenon
(Hint: consider the Memory Wall, CPU Caches, and TLB misses).
