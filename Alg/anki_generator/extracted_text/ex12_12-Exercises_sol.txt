12.1Opening Book Generation
In this task, we want to create an Opening Book (OB) for our Connect Four agent to reduce the search
time in the early game. An opening book is a table of precomputed moves for the first few turns.
You should generate two different opening books:
1.Perfect Opening Book: Contains only moves that lead to the optimal minimax score.
2.Imperfect Opening Book: Contains moves that guarantee a win, even if they are not the optimal
win, as long as they are winning. This relaxes the condition and can speed up generation.
Struct Definition:We recommend the following compactstructto represent an entry in the opening
book. The#pragma packdirective ensures that the compiler does not add padding bytes, minimizing
memory and disk space:
#pragma pack(push, 1)
struct ob_entry {
uint64_t board_a;
uint64_t board_b;
int8_t move;
int8_t score;
};
#pragma pack(pop)
Algorithmic Approach:To keep the size of the opening book manageable, compute it only up to depth
12 and use an asymmetric approach: when it is the bot’s turn, we only need to store and follow the
single best move. When it is the opponent’s turn, we must explore all valid replies, as the opponent
might play anything. Note that the bot could play as the first player or as the second player, so you
must build the book for both scenarios!

12.2Advanced Search Optimization in Connect Four
Iterative Deepening (ID) is a technique where the search is run repeatedly with increasing depth limits.
For example, we first search up to depth 12, then depth 14, then 16, and so on. When reaching the
current depth limit without finding a terminal state, the search returns a score. We consider the variant
where non-terminal positions are evaluated as 0, since it is unclear how to define a suitable heuristic
for Connect Four, even though a good heuristic could potentially improve performance. The purpose
of this approach is to populate the Transposition Table (TT) with good moves. In subsequent, deeper
iterations, these moves can be examined first, which makes alpha-beta pruning more effective.
Aspiration Windows are commonly used in combination with ID. The idea is to start the search using
the best move obtained from the TT with a narrow alpha-beta window around the predicted score. If
the returned score falls outside this window (i.e., is≤αor≥β), the search is repeated with a wider
window.

(e.g., from depth 36 onwards).

12.3Iterative Deepening Search
Iterative Deepening Search repeatedly performs a depth-first search, increasing the maximum search
depth by 1 in each iteration (depth 1, then depth 2, etc.). Thus, it tries to combine the advantages of BFS
and DFS in one algorithm.
In terms of memory requirements, iterative deepening search has the same advantage as depth-first
search over breadth-first search: it requires much less memory.1
One advantage of iterative deepening search over DFS is its behavior in infinite graphs. While a stan-
dard depth-first search can traverse an infinite path without reaching the goal, applying a growing
depth limit forces iterative deepening to examine every node at a shallower depth before exploring
deeper paths.
What other advantage of BFS over DFS does iterative deepening search share?
Solution: Optimality. Because of the layer-by-layer processing (first all nodes up to depth 1, then
depth 2, etc.), the first path found to the goal is guaranteed to be a shortest path, as in breadth-first
search.

Implementation Details
•Classical DP:Computes the fullm×nmatrix. It has a constant overhead per cell.
•Aspiration Window:Computes a narrow band around the main diagonal. If the target
distance exceeds the band width, the computation is repeated with a larger band.
•IDA*:Uses depth-first search with the length difference of the remaining suffixes as an
admissible heuristic. It requires little memory but may recompute overlapping paths.
•A* and Dijkstra:Both algorithms explore the graph systematically. To handle the search
space efficiently, the priority queue is implemented as a circular buffer (bucket queue) of size
3 (for A*) or 2 (for Dijkstra), based on the maximum possible cost increase per step. This keeps
memory usage linear.
•Banded DP:Computes only a fixed-width band around the diagonal. It is fast but does not
guarantee the optimal distance if the true path leaves the band.

tance. A* and Dijkstra also finish quickly.
In Scenario 2, the true distance corresponds exactly to the length difference of the texts. IDA* can
therefore find the optimal path in its first iteration. Banded DP fails to find the optimal distance be-
cause the structural change shifts the optimal path outside the fixed band. The Aspiration Window
approach requires multiple restarts, which increases runtime.
