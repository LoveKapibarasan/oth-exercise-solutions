Decision Problems Are (Often) Sufficient
We focus on decision problems. Let us e.g. consider TSP: GivenNplaces and an
N × N-matrix (cost matrix)AwithA [i][j] specifying the cost to drive from placeito place
j, we want to find “a short round trip” going through all places and returning to the start.
Optimization Vari-
ant optTSP
Input: cost matrix
Output: a shortest round trip
Evaluation Variant evalTSP
Input: cost matrix
Output: the cost of a shortest round trip
Decision Variant decTSP
Input: cost matrix,k∈ℕ
Output: yes (no) if there is a (no) round trip with cost≤k
We can solve evalTSP and optTSP withO(n) questions to decTSP. So “efficient”
algorithms for decTSP lead to “efficient” algorithms for evalTSP and optTSP.

Is Polynomial Time a Reasonable Limit?
Pros
▶ For problems that can be solved in polynomial time, the running time often
grows only moderately, so that even larger inputs can still be solved in a
reasonable time.
▶ For problems that cannot be solved in polynomial time, the running time grows
so fast that even small inputs cannot be solved in a reasonable time (this is
largely independent of technological progress).
▶ Experience shows that algorithms with a high polynomial running time can often
be improved. For “most” problems in P (or FP), algorithms with running time
O(n3)can be found.

Is Polynomial Time a Reasonable Limit?
Cons
▶ There are algorithms with exponential worst-case running time, but very low
average-case running time (e.g., graph coloring can be solved in average-case
running time O(1)).
▶ If the running time is only restricted by a polynomial of high degree, a
polynomial time algorithm is also not feasible.
▶ If the running time is restricted byO(c n)for a smallc, an exponential time
algorithm for instances of medium size is feasible (e.g., Clique can be solved in
timeO(1.19 n)).

Common Properties of these Problems
We do not know any algorithms with polynomial running times for the problems
mentioned.
However, the problems have important similarities:
1. Question about theexistence of certain solutions.
2. Solutions areshort(|potential solution|≤p(|input|)).
3. Solutions areeasily verifiable(in polynomial time).
▶ ⟨m,K,b⟩∈TSP⇔∃round trip with total costs≤b

Dealing with NP-Complete Problems
We have seen that NP-complete problems can only be solved in polynomial time ifP=NP .
On the other hand, these problems often arise in practical contexts.
What options are there for handling NP-complete problems?
▶ Approximation algorithms: polynomial-time algorithms with a provable error
bound; only applicable to optimization problems
▶ Heuristics: try to generate good solutions fast with rules of thumb; suitable for
decision and optimization problems
▶ Exact algorithms: use exponential-time algorithms, but try to keep exponential
part as low as possible, e.g.,O(1.19 n)-algorithm for CLIQUE

Remark 3.16

The RSA Cryptosystem
▶ In 1977 Ronald Rivest, Adi Shamir and Leonard Adleman published with RSA the first
public-key cryptosystem, which —as a side effect— solves the key exchange as well.
▶ In 1985 Taher Elgamal developed a public-key cryptosystem based on the idea of the
Diffie-Hellman key exchange.
General operation of public-key cryptosystems
▶ Each participant possesses a key pair: (public key e, private key d).
▶ The public key is written to a public directory, the private key remains secret.
▶ If Alice wants to send an encrypted message to Bob, she uses Bob’s public key to
encrypt the message. (no shared key, no communication with Bob)
